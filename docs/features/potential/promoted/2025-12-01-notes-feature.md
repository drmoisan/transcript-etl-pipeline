## Problem / Why

The pipeline cannot ingest and merge Granola.ai markdown notes with transcripts to produce a single consolidated, consistently formatted document when notes and transcript arrive at different times.

## Proposed Behavior

- Accept notes from clipboard or markdown file, normalize, and place them at the top of the document.
- Accept transcript from clipboard or file, normalize, and place it at the bottom of the document.
- Support creating a new consolidated document or adding/replacing notes/transcript in an existing document.
- When adding notes, tag each block with a user-provided label or autogenerated timestamp; adding transcript appends to the bottom.

## Acceptance Criteria (early draft)

- [ ] Ingest notes from clipboard or markdown file.
- [ ] Ingest transcript from clipboard or file.
- [ ] New vs existing document mode is prompted and respected.
- [ ] Notes always appear above transcript; new notes appear above prior notes.
- [ ] Transcript always appears below any prior transcript content.
- [ ] Add vs replace behaviors work for notes and transcript.
- [ ] Notes blocks are labeled (user label or timestamp) when multiple blocks exist.
- [ ] Output formatting matches existing ETL conventions.

## Constraints & Risks

- Must reuse existing normalization/formatting conventions to avoid regressions.
- Deterministic merge logic; predictable headers/anchors for parsing existing docs.
- Handle invalid inputs (non-markdown notes, empty clipboard) with clear errors.
- Avoid breaking existing transcript-only flows.

## Test Conditions to Consider

- [ ] Unit: normalization of notes/transcript; add/replace merge logic; label generation.
- [ ] Integration: new vs existing document flows; notes-only, transcript-only, both; multi-import scenarios.
- [ ] CLI/API examples: flags for notes source/file, modes (add/replace), new vs existing document paths.
